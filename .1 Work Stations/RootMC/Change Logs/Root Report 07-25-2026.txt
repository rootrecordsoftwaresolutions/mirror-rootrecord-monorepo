================================================================================
1. SYNOPSIS
================================================================================

RootMC is a dual-host Paper network: Towny (main economy / towns / nations) and
Claims (satellite claims / try / official peer). Players reach the network via
play.rootmc.net. Public surface is rootmc.net (site), api.rootmc.net (Worker),
and map.rootmc.net (BlueMap). Gold (G) is the player currency; automated grants
debit treasury, not direct mint. Shockbyte MySQL is authoritative for economy,
playtime, bonds, shops, and reporting; Cloudflare D1 holds accounts, linking,
Discord coordination, and governance.

Both hosts restarted cleanly on 07/25 with no errors. Economy heartbeats, bond
settlement, licenses, cloud status pushes, and Discord startup relays all OK.
Towny reached Paper Done in 26.5 s and Discord-ready in ~41.5 s total; Claims
Done in 14.9 s and Discord-ready in ~30 s — same post-Done Stage B pattern
(~15 s) on both hosts. Claims runtime (2 GB / 2 vCPU): steady CPU ~3–12%, RAM sawtooth ~16–47%.
Towny runtime (6 GB / 2 vCPU): post-ready CPU mostly under 10% (was ~40–60%
pre-restart); RAM settling ~8–18% sawtooth → ~12% stable (~0.7 GB).

4. BOOT PROCESS (architecture)
================================================================================

Paper boot is two wall-clock stages:

  Stage A — Plugin enable + world load (synchronous)
    Worlds load, plugins call onEnable(), listeners/commands register,
    MySQL/tables open, query/GS4/Votifier bind. Ends with Paper's
    "Done (Xs)!" — that X is total Stage A wall time from JVM start.

  Stage B — Delayed init + scheduled post-boot tasks (tick timers)
    After "Done", the main thread runs "Running delayed init tasks" then
    queued Bukkit runTask / runTaskLater work. Most RootMC cloud, Discord,
    census, territory, and shop work intentionally lands HERE so it does
    not stretch Stage A.

Scheduled post-boot delays (20 TPS → 20 ticks = 1s wall-clock when TPS is
healthy; during cold boot ticks can stretch ~1–2s of extra wall time):

  Task                              Delay from schedule point
  --------------------------------  --------------------------------
  World borders (Root-Ops/Admin)    20 ticks  (~1s after admin enable)
  Item census startup scan          40 ticks  (~2s after ItemInfo enable)
  PAPI expansion retries            next tick, +40, +100 (~0 / 2s / 5s)
  Territory zones rebuild           100 ticks (~5s after Territories enable)
  Shop MySQL backfill (RootMC)      200 ticks (~10s after RootMC enable)
  Discord "Startup complete"        300 ticks (~15s after Root-Ops enable)
  Cloud status push (Root-Times)    first timer fire (~5s interval config)

Design intent: Discord startup notify is intentionally late (~15s after
Root-Ops enables, which is near the end of Stage A) so Stage B quiet work
finishes before #ingame-chat is told the host is ready.
